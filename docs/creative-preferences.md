# Creative Preferences

**Version:** 0.1  
**Status:** Living studio system  
**Audience:** Fred, collaborators, and AI coding/design tools

Read this document before making a studio-level decision. A user prompt wins for
game-specific content and direction; this document wins for preferences that
define how the studio works across projects.

This is a living record of Fred's preferences for game projects. Update it when a preference becomes clear through conversation or iteration.

## Current preferences

- Browser-first and easy to share with the general public.
- Showcase quality matters more than breadth of content.
- A game should feel authored, not like a generic technical demo.
- AI-assisted development should be visible and understandable to students and curious observers.
- Different games should be allowed to develop distinct identities and mechanics.
- A game should be forkable so other people can riff on it.

## The three layers

### The Lock

These are the current studio-level commitments:

- Browser-first delivery.
- Prompt-driven development.
- Showcase-quality intent.
- Publicly understandable project structure.
- Independent games that can be forked or extracted.
- Performance and accessibility treated as part of polish.

### The Canvas

Each game chooses its own genre, camera, mechanics, visual language, pacing,
audience, and content boundaries. The Canvas is where a game becomes specific.
The game-specific README and design documents are authoritative for that game.

### The Remix

Experimental departures are welcome. A Remix should be labeled as an experiment,
tested in a playable slice, and either promoted into the studio system or kept
local to its game after we learn from it.

## AI application rule

When a prompt conflicts with the Lock, ask whether the request is intentionally
changing the studio system. When a prompt conflicts only with the Canvas of one
game, honor the game's direction and document the exception locally.

## Open questions

- Preferred camera perspectives and game genres.
- Desired mobile support level for each game.
- Whether public repositories should include full development history or only polished releases.
